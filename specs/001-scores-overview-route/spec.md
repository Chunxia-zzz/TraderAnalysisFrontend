# Feature Specification: 机会速览页面可达

**Feature Branch**: `001-scores-overview-route`

**Created**: 2026-11-01

**Status**: Implemented — **未完全收敛**，6 项差距见 `tasks.md` § Phase 6: Convergence

**Input**: User description: "修复机会速览死链并让页面可达"

## 背景与问题

首页底部有一个「机会速览」按钮，点击后落到**空白页** —— 该页面本身已经完整实现（分档列表、筛选、止盈止损展开），
但用户无法通过任何正常途径打开它。

后端接口文档中，「全标的评分速览」与「止盈止损计算」两个接口标注的消费页面**都包含本页**，
说明它在设计上是活的页面，不是废弃草稿。**偏差在"可达性"，不在"页面内容"。**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从首页进入机会速览，一眼看到今天该关注什么 (Priority: P1)

用户打开首页，看完理念介绍后想知道「今天有哪些标的值得看」。点击「机会速览」按钮，
进入一个按评分分档排列的清单页，可以在「全部 / 严重超卖且站上MA5 / 严重超卖 / 超卖 / 中性」之间切换，
每个分档的条数直接显示在按钮上。

**Why this priority**: 这是该页面存在的唯一理由。没有它，页面等于不存在；其余故事都建立在这个入口之上。

**Independent Test**: 从首页点击「机会速览」→ 页面渲染出分档清单，五个筛选按钮均显示正确条数，
点击任一筛选后只剩对应分档的标的。

**Acceptance Scenarios**:

1. **Given** 首页已加载，**When** 用户点击「机会速览」按钮，**Then** 进入机会速览页并显示分档清单，**不是**空白页
2. **Given** 机会速览页已加载且数据非空，**When** 用户点击「严重超卖」筛选，**Then** 只显示该分档标的，且按钮上标出的条数与实际显示条数一致
3. **Given** 用户在机会速览页，**When** 用户点击任一只标的，**Then** 跳转到该标的的 K 线页并带上该标的代码
4. **Given** 用户已浏览机会速览页，**When** 用户直接刷新浏览器（或在地址栏输入该页地址），**Then** 页面正常打开，**不是** 404 或白屏

### User Story 2 - 就地查看某只标的的止盈止损，不用跳走 (Priority: P2)

用户在「严重超卖」或「超卖」分档里看到感兴趣的标的，想立刻知道止损位、止盈位和风险回报比，
于是点该行的「止盈损」展开一行，看完再收起。

**Why this priority**: 这是本页区别于其他信号页的独有能力（别处没有），但它是 P1 之上的增强 —— 没有它页面仍可用。

**Independent Test**: 在任一可展开分档里点击「止盈损」，该行下方出现止损/止盈/风险回报比三项数值；再次点击收起。

**Acceptance Scenarios**:

1. **Given** 标的列表已显示，**When** 用户点击某行的「止盈损」，**Then** 该行下方展开止损价、止盈价、风险回报比
2. **Given** 某行的止盈损已展开，**When** 用户再次点击「止盈损」，**Then** 该行收起
3. **Given** 某标的的止盈损数据不可用，**When** 用户点击「止盈损」，**Then** 展示可读的提示文案，**不是**空白、报错弹窗或页面崩溃
4. **Given** 用户点击「止盈损」，**When** 该次点击发生，**Then** **不触发**跳转到 K 线页（展开与跳转是两种意图，不能互相误触）

### User Story 3 - 回看历史某一天的机会清单 (Priority: P3)

用户想复盘「上周三的机会清单长什么样」，于是用日期选择器切到那一天。

**Why this priority**: 对复盘有价值，但日常使用频率低于 P1/P2，且缺失时页面主体仍成立。

**Independent Test**: 选择历史日期后，清单内容随之变化；清空日期后回到最新一天。

**Acceptance Scenarios**:

1. **Given** 页面默认展示最新数据，**When** 用户选择某个历史日期，**Then** 清单切换为该日期的数据
2. **Given** 用户已选择历史日期，**When** 用户清空日期选择，**Then** 清单回到最新一天

---

### Edge Cases

- **无数据**：所选日期没有任何评分数据时，页面显示后端给出的提示文案，保持页面结构可用，**不显示错误告警**（本项目约定：无数据是「正常状态」，不是「失败」）。
- **部分分档为空**：某个分档条数为 0 时该分档区块不出现；「全部」视图下不应出现空白区块。
- **单只标的数据不完整**：某只标的缺少评分值时，**不得**因此让整页渲染失败或整行消失；应显示可读占位而非崩溃。
- **接口请求失败**：网络或服务异常时展示可重试的失败提示，而不是永久转圈。
- **重复点击同一行**：「止盈损」展开后再次点击应收起，不应重复请求或状态错乱。
- **直接访问 / 刷新页面地址**：不依赖从首页点击进入，地址栏直接访问必须可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户 MUST 能通过首页「机会速览」按钮进入该页面，**不得**出现空白页
- **FR-002**: 页面 MUST 展示按评分分档的标的清单，分档为：严重超卖（≥80）、超卖（60~79）、中性（<60）
- **FR-003**: 页面 MUST 提供「严重超卖且站上MA5」的可执行机会分档，且仅在该分档有内容时显示
- **FR-004**: 页面 MUST 提供五个筛选视图（全部 / 可执行机会 / 严重超卖 / 超卖 / 中性），每个按钮标出该分档条数
- **FR-005**: 用户 MUST 能点击任一标的跳转到其 K 线页，并带上该标的标识
- **FR-006**: 用户 MUST 能在「严重超卖」与「超卖」分档就地展开某只标的的止盈止损（止损价、止盈价、风险回报比），并可收起
- **FR-007**: 展开止盈止损 MUST NOT 触发跳转
- **FR-008**: 用户 MUST 能按日期筛选，并可清空回到最新一天
- **FR-009**: 无数据时 MUST 展示后端提示文案，且 MUST NOT 呈现为错误状态
- **FR-010**: 单只标的数据不完整时 MUST NOT 导致整页渲染失败
- **FR-011**: 用户 MUST 能直接访问该页地址并刷新而正常显示（不依赖从首页点击进入）

### Key Entities

- **机会清单**：某个交易日的全标的评分分组视图，含总条数、各分档条数、各分档的标的集合
- **标的条目**：代码、名称、评分、是否站上 MA5、EMA 飘带状态、动量分（部分分档才有）
- **止盈止损**：某标的的止损价、止盈价、风险回报比；可能不可用

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从首页点击「机会速览」到清单可见，耗时不超过 3 秒（本地网络、数据已就绪前提下）
- **SC-002**: 五个筛选按钮显示的条数与点击后实际渲染的行数**逐项一致**，误差为 0
- **SC-003**: 直接访问该页地址并刷新，**100%** 能正常打开（不是 404 / 白屏）
- **SC-004**: 无数据、单只标的数据缺失、接口失败三种异常下，**均无**页面崩溃或永久 loading
- **SC-005**: 展开止盈止损的误跳转次数为 **0**

## Assumptions

- 该页面代码已完成且可正常工作，本次**不重写页面**；问题仅在于用户无法到达它。
- 「机会速览」与「交易信号」页（`/momentum-leaders`）**是两个不同视角**，本次**不合并**：
  前者按评分分档看「跌得多深」，后者看 EMA 交叉与主升主跌。合并属独立议题。
- **不新增**顶部导航入口。首页按钮是该页的既定入口，与现有导航结构一致；是否进导航另行决定。
- 页面视觉与交互**保持现状**，本次不改版。
- 后端两个相关接口已实现且线上可用，本次**不改后端**。

## 明确不做（Out of Scope）

- 不改页面视觉风格、布局与文案
- 不合并「机会速览」与「交易信号」
- 不新增顶部导航入口
- 不改后端接口与数据口径
- 不新增排序、导出、自选等新功能
